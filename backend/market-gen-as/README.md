# market-gen-as

Генератор ринкових оновлень на AssemblyScript, який компілюється у WebAssembly.

Це дзеркало еталонної TypeScript-версії з `../market-gen-ts`: та сама структура тек, ті самі класи, методи й порядок викликів. З тим самим seed і налаштуваннями обидві версії видають однакові оновлення, і це перевіряють тести.

## Структура

| AssemblyScript (`assembly/`) | TypeScript (`../market-gen-ts/src/`) |
|---|---|
| `constants.ts` | `constants.ts` |
| `config/simulation-config.ts` | `config/simulation-config.ts` |
| `model/side.ts`, `order.ts`, `quote.ts`, `market-update.ts` | ті самі файли |
| `market-model/price.ts`, `quantity.ts` | ті самі файли |
| `simulator.ts` | `simulator.ts` |
| `utils/random-generator.ts` | `utils/random-generator.ts` |
| `index.ts`: межа Wasm, функції для воркера | немає, функції викликаються напряму |
| немає: таймерів у Wasm немає | `scheduler.ts`, лишається у воркері |

## Чим відрізняється від TypeScript-версії

Відмінності лише там, де цього вимагає AssemblyScript. У коді кожна позначена коментарем.

- **Числа.** Ціни й кількості мають тип `i32`, стан генератора випадкових чисел `u32`.
- **Округлення.** Замість `Math.round` з дробами цілочисельне ділення з додаванням половини дільника. Результат той самий.
- **Генератор випадкових чисел.** Множення `u32` саме обрізається до 32 біт, тому не потрібні `Math.imul` і `>>> 0`. Послідовність та сама.
- **Сторона угоди.** `getPriceDelta` приймає `Side` замість рядка `'buy' | 'sell'`, бо AssemblyScript не має рядкових union-типів.
- **Межі налаштувань.** Окремі константи замість об'єкта `SIMULATION_LIMITS`.
- **Перевірка налаштувань.** Повертає біти некоректних полів, а не масив помилок з текстом. Тексти помилок формує воркер.

## Функції для воркера

| Функція | Що робить |
|---|---|
| `validateConfig(instrumentCount, updatesPerBatch, batchIntervalMs)` | перевіряє налаштування, повертає біти помилок, 0 означає коректно |
| `init(instrumentCount, updatesPerBatch, batchIntervalMs, seed)` | починає новий запуск і скидає попередній; з поганими налаштуваннями нічого не змінює й повертає біти помилок |
| `nextBatch()` | генерує батч і повертає вказівник на буфер, 0 якщо запуск не ініціалізовано |
| `dispose()` | завершує запуск |

Буфер це плоский масив `i32`, по `FIELDS = 7` чисел на оновлення: інструмент, ціна угоди, кількість угоди, bid, ask, кількість на bid, кількість на ask. Константи `F_*` задають зміщення кожного поля. Воркер читає буфер так:

```ts
const pointer = exports.nextBatch();
const data = new Int32Array(exports.memory.buffer, pointer, updatesPerBatch * 7);
```

Вказівник дійсний лише до наступного виклику `nextBatch`, тому дані треба скопіювати одразу.

## Пам'ять

Модуль збирається з runtime `incremental`, тобто зі збирачем сміття. Кожне оновлення створює об'єкти `Order` і `MarketUpdate`, і без збирача сміття пам'ять росла б безмежно. Тест перевіряє, що після 2 000 000 оновлень пам'ять не зростає.

## Запуск

```bash
npm install
npm run build   # build/market_gen.wasm
npm test        # збирає модуль і запускає тести
```

Тести лежать у `tests/generator.spec.ts` і перевіряють скомпільований `.wasm`:

- паритет із TypeScript-версією на чотирьох наборах seed і налаштувань;
- межі налаштувань і те, що невдалий `init` не ламає поточний запуск;
- розмір батча й інваріанти ТЗ на 100 000 оновлень;
- збереження стану між батчами і повне скидання при новому `init`;
- стабільну пам'ять за тривалої роботи.
