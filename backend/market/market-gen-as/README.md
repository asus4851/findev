# market-gen-as

Генератор рыночных обновлений на AssemblyScript, компилируемый в WebAssembly. Это «биржа» бэкенд-домена: в Wasm работают случайность, цены и стакан.

Это зеркало эталонной TypeScript-версии из `../market-gen-ts`: та же структура папок, те же классы, методы и порядок вызовов. С тем же seed и настройками обе версии выдают одинаковые обновления, и это проверяют тесты.

## Структура

| AssemblyScript (`assembly/`) | TypeScript (`../market-gen-ts/src/`) |
|---|---|
| `constants.ts` | `constants.ts` |
| `config/simulation-config.ts` | `config/simulation-config.ts` (реэкспорт из `../contracts`) |
| `model/side.ts`, `order.ts`, `quote.ts`, `market-update.ts` | те же файлы |
| `market-model/price.ts`, `quantity.ts` | те же файлы |
| `simulator.ts` | `simulator.ts` |
| `utils/random-generator.ts` | `utils/random-generator.ts` |
| `index.ts`: граница Wasm, функции для воркера | нет, функции вызываются напрямую |
| нет: таймеров в Wasm нет | `scheduler.ts`, только в эталоне |

## Чем отличается от TypeScript-версии

Отличия только там, где этого требует AssemblyScript. В коде каждое помечено комментарием.

- **Числа.** Цены и количества имеют тип `i32`, состояние генератора случайных чисел `u32`.
- **Округление.** Вместо `Math.round` с дробями целочисленное деление с добавлением половины делителя. Результат тот же.
- **Генератор случайных чисел.** Умножение `u32` само обрезается до 32 бит, поэтому не нужны `Math.imul` и `>>> 0`. Последовательность та же.
- **Сторона сделки.** `getPriceDelta` принимает `Side` вместо строки `'buy' | 'sell'`, потому что AssemblyScript не поддерживает строковые union-типы.
- **Границы настроек.** Отдельные константы вместо объекта `SIMULATION_LIMITS`.
- **Проверка настроек.** Возвращает биты некорректных полей, а не массив ошибок с текстом. Тексты ошибок формирует воркер.

## Экспортируемые функции

| Функция | Что делает |
|---|---|
| `init(instrumentCount, updatesPerBatch, batchIntervalMs, seed)` | начинает новый запуск и сбрасывает предыдущий; с плохими настройками ничего не меняет и возвращает биты ошибок |
| `nextBatch()` | генерирует батч и возвращает указатель на буфер, 0 если запуск не инициализирован |
| `dispose()` | завершает запуск |
| `validateConfig(instrumentCount, updatesPerBatch, batchIntervalMs)` | проверяет настройки без запуска, возвращает биты ошибок; воркер её не вызывает (он проверяет настройки через `init`), используют её тесты |

Буфер — плоский массив `i32`, по `FIELDS = 7` чисел на обновление: инструмент, цена сделки, количество сделки, bid, ask, количество на bid, количество на ask. Константы `F_*` задают смещение каждого поля. Воркер читает буфер так:

```ts
const pointer = exports.nextBatch();
const data = new Int32Array(exports.memory.buffer, pointer, updatesPerBatch * 7);
```

Указатель действителен только до следующего вызова `nextBatch`, поэтому данные нужно прочитать сразу.

## Память

Модуль собирается с runtime `incremental`, то есть со сборщиком мусора. Каждое обновление создаёт объекты `Order` и `MarketUpdate`, и без сборщика память росла бы бесконечно. Тест проверяет, что после 2 000 000 обновлений память не растёт.

## Запуск

```bash
npm install
npm run build   # build/market_gen.wasm
npm test        # собирает модуль и запускает тесты
```

Тесты лежат в `tests/generator.spec.ts` и проверяют скомпилированный `.wasm`:

- паритет с TypeScript-версией на четырёх наборах seed и настроек;
- границы настроек и то, что неудачный `init` не ломает текущий запуск;
- размер батча и инварианты ТЗ на 100 000 обновлений;
- сохранение состояния между батчами и полный сброс при новом `init`;
- стабильную память при длительной работе.
